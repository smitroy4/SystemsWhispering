## Video 12: Object Oriented Programming in Java | Classes, Objects, new Keyword

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> "Welcome back, Coder Army, to our Java series. Today we enter the world of Object-Oriented Programming (OOP). Real-world entities have properties (state) and behaviors. In Java, a **Class** acts as a blueprint or template, while an **Object** is an instance created in heap memory using the `new` keyword. 
> When we declare `Student s1 = new Student();`, `s1` is a reference variable residing on the stack that points to the actual `Student` object allocated in heap memory. Fields like `name`, `age`, and `rollNumber` hold state, while methods represent behavior. Accessing members is done via the dot operator (`s1.name = "Aditya";`)."

### Key Architectural Concepts
- **Class vs Object**: A class defines the template structure; an object allocates dynamic runtime memory.
- **Memory Allocation**: The `new` keyword dynamically allocates memory on the Heap, while the reference variable resides on the Execution Stack.
- **Encapsulating Behavior**: Methods defined inside a class operate directly on the instance variables of the calling object via implicit `this`.

## Video 13: Constructors in Java | Constructor Chaining, Overloading & this

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> "Constructors are special member functions called automatically during object instantiation to initialize state. They share the exact name of the class and have no return type—not even `void`. 
> If no constructor is written, Java injects a **Default Constructor** that initializes fields to default values (`null`, `0`, `false`). Once a custom constructor (like a **Parameterized Constructor**) is defined, the automatic default constructor is suppressed. 
> **Constructor Chaining** allows one constructor to invoke another within the same class using `this(...)` or in a parent class using `super(...)`. `this` refers to the current object instance and resolves naming collisions between parameters and field names."

### Key Architectural Concepts
- **Constructor Rules**: Same name as class, no return type, automatically invoked with `new`.
- **Constructor Overloading**: Multiple constructors differentiated by parameter list length or types.
- **Constructor Chaining**: Streamlining initialization logic using `this(...)`, which must be the first statement in the constructor body.

## Video 14: Objects Deep Dive | Size, Call by Value vs Reference | Shallow vs Deep Copy

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> "In Java, object memory layout consists of three parts: **Object Header** (Mark Word + Class Pointer, typically 12–16 bytes), **Instance Data** (fields aligned by primitive/reference sizes), and **Memory Padding** (padding to align total size to 8-byte multiples).
> Java is strictly **Call-by-Value**. When passing objects to methods, Java copies the *value of the reference variable* (memory address), not the object itself. Therefore, modifying object internal properties affects the original heap object, but reassigning the reference parameter inside the method does not change the caller's reference.
> **Shallow Copy** copies field values directly—retaining references to shared nested objects—whereas **Deep Copy** creates entirely independent duplicates of both the root object and all nested referenced objects."

### Key Architectural Concepts
- **Heap Memory Layout**: Object Header (12B/16B) + Instance Fields + 8-byte Padding alignment.
- **Call-by-Value Mechanics**: References are passed by copying address values on the stack frame.
- **Shallow vs Deep Copy**: Reference duplication vs recursive cloning of nested object graphs.

## Video 15: Static & Final in Java | Static Methods, Blocks & String[] args

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> "The `static` keyword binds variables and methods to the **Class (Method Area/Metaspace)** rather than individual heap instances. Static fields are shared across all instances, saving memory. Static methods can only access other static members directly and cannot reference `this` or `super` because no specific instance exists during execution.
> **Static Initialization Blocks** execute once when the class is loaded into memory by the ClassLoader, prior to any constructor calls.
> The `final` keyword creates immutability: `final` variables cannot be reassigned, `final` methods cannot be overridden, and `final` classes cannot be extended."

### Key Architectural Concepts
- **Static Scope**: Class-level variables stored in Metaspace; shared state across all heap objects.
- **Execution Order**: Static blocks -> Instance initialization blocks -> Constructor calls.
- **Final Keyword**: Immutability constraints across variables, methods (disables dynamic dispatch), and classes (disables inheritance).

## Video 16: Encapsulation & Inheritance in Java | Java Packages & Super Keyword

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> "**Encapsulation** bundles state and behavior together while restricting direct variable access using `private` modifiers, exposing controlled access through public getters and setters.
> **Inheritance** establishes an *IS-A* relationship using `extends`. The child class inherits parent fields and methods. 
> Java uses **Packages** to organize namespace hierarchies and enforce access levels (`private`, `default/package-private`, `protected`, `public`).
> The `super` keyword references the immediate parent object—allowing invocation of overridden parent methods or triggering parent constructors via `super(...)`."

### Key Architectural Concepts
- **Access Modifiers**: `private` (class-only), `default` (package-only), `protected` (package + subclasses), `public` (universal).
- **Inheritance & Super**: Facilitates code reuse and polymorphism; `super(...)` delegates parent initialization.
- **Diamond Problem**: Java disallows multiple class inheritance to eliminate ambiguity in method resolution.

## Video 17: Abstraction & Polymorphism in Depth | Abstract Class vs Interfaces

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> "**Abstraction** hides complex internal implementation details, exposing only essential operational interfaces. **Polymorphism** ('many forms') allows an object reference of a supertype to point to any subtype instance.
> **Compile-Time Polymorphism** is achieved via **Method Overloading** (same method name, different signature), resolved at compilation.
> **Runtime Polymorphism** is achieved via **Method Overriding** (subclass provides specific implementation of parent method), resolved dynamically at runtime using Virtual Method Tables (vtables).
> Static, private, and final methods cannot be overridden because they do not participate in dynamic dispatch."

### Key Architectural Concepts
- **Abstract Classes vs Interfaces**: Abstract classes express identity and shared state; interfaces define capability contracts.
- **Dynamic Method Dispatch**: Resolves overridden method execution based on actual runtime heap object type.
- **Polymorphism Rules**: Instance fields and static methods are not polymorphic—they bind based on reference type at compile time.

## Video 18: AutoBoxing, Abstract classes & POJOs | Why only one public class in java file

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> "Java restricts `.java` files to **at most one public class**, whose name must strictly match the filename. This allows the Java compiler (`javac`) and JVM ClassLoader to quickly locate entry-point bytecodes without scanning entire files.
> **Wrapper Classes** (`Integer`, `Double`, `Boolean`) wrap primitives into reference objects. **Autoboxing** automatically converts primitives to wrapper objects (via `valueOf()`), while **Unboxing** extracts primitives (via `intValue()`).
> Wrapper classes utilize internal caching (e.g., `IntegerCache` for values -128 to 127) for performance optimization.
> **POJO (Plain Old Java Object)** refers to unconstrained classes containing private fields, default constructors, and getters/setters without dependency on enterprise frameworks."

### Key Architectural Concepts
- **Compilation Structure**: 1 public class per file matching filename for fast bytecode lookup.
- **Autoboxing Internals**: `Integer.valueOf(x)` uses cached instances between -128 and 127.
- **POJO Models**: Anemic domain models vs rich domain models.

## Video 19: Java Nested Classes | Static Nested, Inner, Local & Anonymous Classes

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> "Java supports four types of nested classes:
> 1. **Static Nested Classes**: Associated with outer class name (`Outer.Inner`), do not hold an implicit reference to outer instance, cannot access outer non-static fields directly.
> 2. **Inner (Non-Static) Classes**: Bound to an outer instance (`outerObj.new Inner()`), maintain an implicit reference (`Outer.this`) to the outer object, can access all outer fields including `private`.
> 3. **Local Classes**: Defined inside a method body; can access local method variables only if they are `final` or **effectively final**.
> 4. **Anonymous Inner Classes**: Unnamed one-time classes instantiated on the fly, commonly used for overriding method implementations inline."

### Key Architectural Concepts
- **Implicit Reference**: Non-static inner classes hold hidden references to outer instance, causing potential memory leaks if prolonged.
- **Effectively Final Rule**: Local variables captured by local/anonymous classes cannot be modified after initialization.
- **Use Cases**: Encapsulation of helper classes, builder patterns, and inline listener implementations.

## Video 20: Java I/O Deep Dive | InputStreams, System.in, Scanner vs BufferedReader

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> "Java I/O is built around **Streams**—sequences of data flowing byte-by-byte or character-by-character.
> `InputStream` and `OutputStream` operate on raw 8-bit bytes, while `Reader` and `Writer` operate on 16-bit Unicode characters.
> `System.in` is an instance of `InputStream`. `InputStreamReader` acts as a bridge, converting byte streams into character streams.
> `BufferedReader` buffers character input in a 8KB memory buffer for fast reading using `readLine()`, whereas `Scanner` uses regex parsing, making it slower for high-throughput I/O."

### Key Architectural Concepts
- **Byte Streams vs Character Streams**: 8-bit raw binary data handling vs 16-bit UTF-16 character decoding.
- **Decorator Pattern in I/O**: Wrapping `System.in` inside `InputStreamReader` and `BufferedReader`.
- **I/O Performance**: `BufferedReader` is thread-safe and faster; `Scanner` adds parsing overhead.

## Video 21: Immutable Classes in Java | How to Create Immutable Objects

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> "An **Immutable Class** produces objects whose state cannot be altered after construction. To design an immutable class:
> 1. Declare class as `final` (prevents subclassing and overriding).
> 2. Make all fields `private` and `final`.
> 3. Do not provide setter methods.
> 4. Initialize all fields via constructor.
> 5. Perform **Defensive Copying** for mutable objects (like `Date` or custom objects) passed into constructor and returned from getters to prevent reference leaking."

### Key Architectural Concepts
- **Immutability Principles**: Thread safety without synchronization, security, hash code stability.
- **Defensive Copying**: Creating new copies of mutable reference fields in constructors and getters.

## Video 22: Most Important Class in Java | Object Class (equals, hashCode, toString)

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> `java.lang.Object` is the root superclass of all Java classes.
> Key methods:
> - `toString()`: Returns string representation (`ClassName@HexHashCode` by default; overridden for readable output).
> - `equals(Object obj)`: Compares reference equality (`==`) by default; overridden to compare logical equality of field values.
> - `hashCode()`: Returns integer hash code for hashing data structures. **HashCode Contract**: If two objects are equal according to `equals()`, they MUST produce the exact same `hashCode()`.
> - `getClass()`: Returns runtime `Class` object (final method).
> - `clone()`: Creates shallow copy of object (requires `Cloneable` marker interface)."

### Key Architectural Concepts
- **Equals & HashCode Contract**: Breaking this contract corrupts `HashMap` and `HashSet` lookups.
- **Marker Interfaces**: `Cloneable` signals runtime permission for object cloning.

## Video 23: Java Enums | Why Not Use int/String for Constants?

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> **Enums** (`enum`) represent type-safe predefined sets of constants, replacing error-prone integer or string constants.
> Internally, an enum is compiled into a `final` class extending `java.lang.Enum`.
> Each enum constant is a `public static final` instance of the enum class itself created at class loading.
> Enums have `private` constructors (disabling external instantiation), support custom fields/methods, and provide built-in methods like `values()`, `valueOf()`, `ordinal()`, and `name()`."

### Key Architectural Concepts
- **Type Safety**: Enums eliminate invalid constant assignments at compile time.
- **Enum Internals**: Instances are singleton constants initialized inside static block.

## Video 24: Java Interfaces Deep Dive | Default Methods, Functional, Marker Interfaces

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> Java interfaces define contracts. Fields in interfaces are implicitly `public static final`.
> **Java 8 Enhancements**:
> 1. **Default Methods**: Methods with default implementation (`default` keyword) allowing interface evolution without breaking existing implementing classes.
> 2. **Static Methods**: Utility methods defined inside interfaces.
> **Functional Interface**: Interface with **exactly one abstract method** (annotated with `@FunctionalInterface`), serving as target types for Lambda expressions.
> **Marker Interface**: Interface with no methods (e.g., `Serializable`, `Cloneable`), marking classes for special JVM treatment."

### Key Architectural Concepts
- **Interface Evolution**: Default methods prevent API breakage during library upgrades.
- **Diamond Problem Resolution in Interfaces**: Classes implementing multiple interfaces with conflicting default methods must explicitly override the method.

## Video 25: Java Strings | String Pool, Immutability, Internals

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> Strings in Java are immutable sequence objects (`final class String`).
> **String Constant Pool (SCP)**: A dedicated memory region inside the Heap. Literals (`String s = "hello";`) are stored in SCP and shared among reference variables to conserve memory.
> Creating strings via `new String("hello")` forces creation of an object in general Heap memory as well as placing the literal in SCP.
> `intern()` method pushes a heap string reference into the String Pool, returning the canonical pool reference."

### Key Architectural Concepts
- **Memory Optimization**: SCP minimizes string duplication across execution frames.
- **Immutability Benefits**: Thread safety, string pool caching, security in classloading & database URLs.

## Video 26: Java Strings Part 2 | All String Methods + StringBuilder vs StringBuffer

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> String operations like concatenation (`+` or `concat()`) create new String objects due to immutability, causing memory overhead in loops.
> **`StringBuilder`**: A mutable sequence of characters backed by a dynamic byte/char array. Fast and non-synchronized (not thread-safe).
> **`StringBuffer`**: A mutable sequence of characters where methods are `synchronized` (thread-safe, suitable for multithreaded operations).
> Both utilize dynamic buffer expansion (doubling capacity when full)."

### Key Architectural Concepts
- **Mutability Mechanics**: Modifying character arrays in place avoids continuous heap allocation.
- **StringBuilder vs StringBuffer**: Single-threaded high performance (`StringBuilder`) vs thread-safe synchronized modification (`StringBuffer`).

## Video 27: Java Generics Deep Dive | Bounded Types using extends

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> **Generics** enforce compile-time type safety and eliminate runtime `ClassCastException` and manual casting.
> **Generic Classes & Methods**: Parameterized with type placeholders (`Box<T>`).
> **Bounded Type Parameters**: Restrict allowed type arguments using `extends`. `class Box<T extends Number>` restricts `T` to `Number` and its subclasses (`Integer`, `Double`), enabling access to `Number` methods inside the generic class."

### Key Architectural Concepts
- **Compile-Time Type Safety**: Catches type mismatch errors during compilation.
- **Upper Bounds**: `<T extends SuperClass>` restricts parameter type hierarchy.

## Video 28: Wildcards in Generics | ?, ? extends, ? super

### Translated Transcript Excerpts & Explanations
> **English Translation:**
> Generics are **invariant**: `List<Dog>` is NOT a subtype of `List<Animal>`, even though `Dog` extends `Animal`.
> **Wildcards (`?`)** restore flexibility:
> 1. **Unbounded Wildcard (`List<?>`)**: Accepts any type list (read-only as `Object`).
> 2. **Upper Bounded Wildcard (`List<? extends Animal>`)**: Accepts `Animal` or subclasses (**PECS: Producer Extends** -> for Reading data).
> 3. **Lower Bounded Wildcard (`List<? super Dog>`)**: Accepts `Dog` or superclasses (**PECS: Consumer Super** -> for Writing data).
> **Type Erasure**: The Java compiler removes generic type parameters during compilation, replacing them with bounds (`Object` or upper bound) for backward compatibility with pre-Java 5 bytecodes."

### Key Architectural Concepts
- **PECS Rule**: Producer Extends (read), Consumer Super (write).
- **Type Erasure**: JVM executes generic code without runtime type parameters, inserting synthetic casts where necessary.
